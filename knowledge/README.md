# knowledge/ — накапливаемая база знаний флота

Паттерн LLM-wiki: знание компилируется один раз и поддерживается актуальным,
вместо переоткрытия с нуля в каждом ресёрче.

## Правило wiki-first (для роли research)

1. **Перед** новым ресёрчем по теме — прочитать соответствующую страницу здесь.
   Если страница есть — ресёрч стартует от неё (проверить свежесть, докопать
   только новое), а не с чистого листа.
2. **После** завершённого ресёрча (карта закрыта) — обновить 1–3 тематические
   страницы: дописать новые факты с датой и ссылкой на полный отчёт, пометить
   устаревшее как `[устарело YYYY-MM-DD]`, снять противоречия.
3. Главные устойчивые выводы (цены, вердикты, регуляторика) — дублировать в
   fact-store профиля research **с датой**, чтобы всплывали в будущих сессиях.
4. Страницу, которой нет, — создать по нижнему формату. Пустых страниц не держать.

## Формат страницы

```markdown
# <Домен>
> Последнее обновление: YYYY-MM-DD · Источники последнего прохода: <путь к отчёту>

## Ключевые факты (проверенные)
- <факт> — [YYYY-MM-DD, confidence, URL/отчёт]

## Открытые вопросы / watch
- <что мониторим>

## История обновлений
- YYYY-MM-DD — <что изменилось, ссылка на артефакт>
```

## Свежесть

Факт без даты не записывать. Доверять странице старше 30 дней без пометки —
только после выборочной перепроверки ключевых цифр.

## Домены

- `llm-providers.md` — рынок LLM-провайдеров/релеев: цены, репутация, подмены.
  Питается provider-bench / routing-ресёрчами и domain-watch мониторингом.
