# docs/knowledge/ — накапливаемая база знаний флота

Паттерн LLM-wiki: знание компилируется один раз и поддерживается актуальным.
Управляемый источник инструкции — canon-скилл `research/knowledge-base`
(деплой во все ресёрч-цели). Эта страница — краткая шпаргалка по каталогу.

## Правила (кратко; полный контракт — в скилле)

1. **Wiki-first**: перед ресэрчем по теме прочитать страницу домена здесь;
   ресэрч стартует от неё, а не с чистого листа.
2. **Обновление до закрытия задачи**: страница обновляется как шаг acceptance
   выполняемой карты, не «когда-нибудь после».
3. Каждый факт: URL-локатор + короткая подтверждающая цитата + `retrieved_at`
   (когда прочитано) + дата действия (если применима) + статус.
4. Статусы: `verified` (цитата сверена по первоисточнику) / `pending`
   (сообщено, не сверено; в выводах не использовать) / `deprecated`.
5. Разделять: **source facts** (из первоисточника) / **выводы** (наша
   интерпретация, с confidence) / **unknowns**.
6. Свежесть — по типу факта: цены/промо — 14 дней; policy/условия — 90 дней
   или до подписанного изменения; структурные факты (юрлицо, владелец) — до
   нового события. Факт старше своего горизонта перепроверять перед
   использованием, не выбрасывать.
7. Пишет в страницу один исполнитель за раз (роль research в своей задаче);
   запись — атомарная перезапись файла, не append-гонка.
8. Fact-store — только устойчивые знания (вердикты, политика, структура
   рынка) с provenance и датой; не дублировать там все цены.
9. Страницы — кэш знаний, не первоисточник: при конфликте решает живой
   источник, а страница обновляется.

## Домены

- `llm-providers.md` — рынок LLM-провайдеров/релеев: цены, репутация, подмены.
- `animation-monetization.md` — монетизация анимационного контента (YouTube).
