# domain-watch — непрерывный мониторинг доменов (роль: research)

## Контракт

| Что | Как |
|---|---|
| Покрытие | ТОЛЬКО источники из `domain-watch.yaml` (feeds + check_urls) |
| НЕ покрывает | Discovery новых событий вне watch-списка; TikTok (нет подтверждённых доступных источников из этой сети); мониторинг запросов между тиками |
| Режим | Ежедневно 09:00, monitor-script с hash-suppression: агент просыпается только при изменении вывода |
| Деградация | Ошибка источника замораживает last-good (`DEGRADED` однократно), повторные ошибки молчат, восстановление — `RECOVERED` однократно |
| Доставка | Дайджест-файл `digests/YYYY-MM-DD.md`; Bot Chat/Kanban этим контуром НЕ пишутся (kanban-инструментов в cron-сессии нет) — material-события фиксируются в секции «→ company» дайджеста |
| Материальность | Определяет агент по критерию `material` конфига; спорное — noise |

## Состав

- `domain-watch.yaml` — конфиг: домены, критерии material, feeds (+опциональный
  `filter` regex по заголовкам), check_urls (+опциональный `expect` regex —
  валидация, что страница жива, а не JS-shell/блок-страница), queries_when_triggered.
- `domain-watch-prompt.md` — промпт агента (подключён cron-задачей).
- `digests/` — ежедневные дайджесты (история в git).
- Скрипт: `scripts/domain_watch_monitor.py` (канонический источник) —
  runtime-копия в `profiles/research/scripts/` (требование cron: имя из scripts/).

## Изменение конфига

Добавить/убрать домен или источник = правка `domain-watch.yaml` в этом
каталоге + коммит. Код менять не нужно. После правки путей скрипта —
перекопировать его в `profiles/research/scripts/` и перезапустить задачу
`hermes -p research cron run <id>`.

## Состояние

`state/domain_watch_state.json` рядом с runtime-копией скрипта (в профиле):
last-good контент и счётчики ошибок по источникам. Удалять только при
сознательном сбросе базлайна (первый прогон после сброса = baseline, будит
агента один раз).
