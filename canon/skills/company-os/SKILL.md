# Company: один цикл до результата

Для управления портфелем и ремонта флота. Полномочия — `APPROVALS.md`, проекты — `PORTFOLIO.md`, общий цикл — `OPERATING_SYSTEM.md` в ventures. Читай относящееся к задаче; история не заменяет текущий контракт.

## Исполнение

1. Один accountable ведёт поручение до результата и нужной поставки. В карте: deliverable, acceptance, границы, актуальный anchor. Один исполнитель по умолчанию; специалисты/независимые gates — под результат или риск.
2. Делегирование передаёт работу, не ответственность. Используй существующий diff и штатный механизм. Ремонт неисправного Hermes допустимо вести напрямую в том же scope с сервисной картой как реестром; не запирай ремонт внутри сломанного пути.
3. Для долгой работы задай checkpoint по ожидаемому артефакту и реальной длительности. Проверь diff/результат, не только PID/heartbeat. Нет полезного прогресса — установи причину, сузь ту же карту или передай её после завершения прежнего claim. Не жди бессрочно и не запускай конкурирующего автора.
4. Проверь acceptance, обязательные review/release gates и фактический handoff. Разделяй source/tests, installed/loaded code, runtime и конечный outcome. Сдерживание сбоя не равно устранению причины; done-card или успешная routine не подтверждают готовность всей фермы.

## Восстановление и продолжение

- Одна каноническая карта на deliverable. Сначала native edit/request-changes/unblock/review; замена — при невозможности восстановления с явным supersedes. Историю сохраняй; не архивируй parent ради обхода гейта.
- Parent — prerequisite, не принадлежность инициативе. Если acceptance ремонта требует validation-карту, ремонт не может удерживать её parent-ребром. Проверяй смысловое взаимное ожидание, не только DAG-циклы.
- `blocked` не значит «нужен владелец». Для внутренней dependency используй parent + unblock и проверь фактический `todo/ready`. Owner/capability hold сохраняется до действительного решения. Не добавляй новый enum/контроллер, когда штатный lifecycle достаточен.
- WAIT требует условия и работающего продолжения: dependency, выбранная native delivery или зарегистрированное расписание. Текст `check_at` и статус `scheduled` сами таймера не создают. Не обещай «дойдёт само» без readback предпосылок и механизма продолжения.
- Повтор запуска — после изменения предпосылки. Различай quota, startup, policy, dependency и ошибку задачи. Отказ не обходится новым ID/профилем/командой; не превращай каждую неудачу в новую карту.

## Проверки и безопасность

- Гипотеза не факт: стек локализует остановку; synthetic operator-run не доказывает worker-fencing bypass. Установи происхождение команды/сессии до архитектурного фикса; неверный диагноз исправь в исходном контракте.
- Cancel/выход клиента/terminal карточки не доказывают остановку managed worker. Только native owner operation с run/PID/creation-time identity; не убивай по старому PID. Gateway не перезапускай из сессии или через wrapper/Scheduled Task.
- Независимая проверка — на точном предмете и допустимой lineage; advisory сабагента не открывает protected release. Проверенные прогоны повторяются только при релевантном изменении.
- Деньги, доступ, необратимость и scanner сохраняются. Config — штатными средствами Hermes. Не читай `.env*`, auth/secrets/dumps; worker не читает control-plane DB напрямую. Не заменяй native runtime своим dispatcher/launcher/watchdog/очередью.

## Эксплуатация и чистота

Company владеет стратегией/капиталом, product — гипотезой, qa/finance — независимыми verdicts. Для ставки: baseline/факт/источник, деньги со scope/периодом, continue/iterate/kill; неизвестное = null. Подробный шаблон `references/outcome-loop.md` нужен для ставки, не каждой операции.

Evidence — в карте; один короткий ежедневный digest, немедленная эскалация по `APPROVALS.md` или критичному риску. Перед «ждёт владельца» проверь свежие body/comments и необходимую просьбу. Прямой owner-request не заменяй дайджестом.

Один текущий контракт и финальный handoff вместо отчёта на каждое действие. История/снимки — вне загружаемых skills; ценные diff/доказательства — attachments или versioned source, не disposable scratch. Приёмка workflow: полезный артефакт → проверка где нужна → native handoff → подтверждённое продолжение. Непроверенное остаётся открытым.
