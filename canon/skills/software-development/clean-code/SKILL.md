# Готовое прежде своего

Источник — `ventures/canon/`; копии в профилях обновляются через canon_deploy.

- Порядок выбора: штатная возможность/код проекта → зрелая поддерживаемая интеграция → своя реализация только для непокрытого требования.
- Выбор начинается с поиска готового: короткий scan существующих решений и свежего опыта прежде своего кода (скилл `research/deep-search`, ветка solution-first; заметки рынка — docs/knowledge/). Вердикт «использовать/адаптировать/писать своё» — с первоисточником; писать своё только при непокрытом требовании.
- Критерии: пригодность, надёжность, безопасность, сопровождение, полная стоимость. Для существенного выбора кратко объясни преимущество над ближайшей альтернативой; типовое решение не требует нового исследования.
- Делай минимальное законченное изменение. Не копируй существенную логику; не вводи зависимость или абстракцию без пользы.
- Поиск аналогов и дублей ограничивай затронутым участком. Детектор — при риске копипасты, не обязательный ритуал для каждой функции/правки текста.
- Проверяй acceptance и конкретный риск существующими тестами/CI. Повтор — при релевантном изменении кода, окружения или условий; обязательные проверки runtime и policy сохраняются.
- Review оценивает решение и корректность, не формальные фразы. Отдельный отчёт, скрипт или слой инструкций нужен только как часть результата.
