# Design quality: визуальное качество выше 85% (флот-канон)

Почему висит на 50–70%: генератор не видит свой результат, «качество» не
измеримо, каждая попытка с нуля, и нет порога остановки. Этот скилл чинит все
четыре причины. Источник — `ventures/canon/`; копию в профиле не править.

## 1. База, не с нуля

- Лендинг/страница начинается с проверенной базы: шаблон (например
  `popular-web-designs/templates`) или якорь-скриншот эталонного качества.
- С чистого листа — только если базы нет. «Придумать стиль» — не этап работы.

## 2. Скоркард (бинарный, по слоям)

Оценка = % зелёных критериев; критерий либо зелёный, либо красный (нет «почти»).

- **Структура (P0):** hero с оффером и одной CTA выше fold; ≤7 секций до футера;
  визуальная иерархия h1 → h2 → body читается за 3 секунды.
- **Адаптив (P0):** 375 / 768 / 1440 без горизонтального скролла и наездов.
- **Контент (P0):** без lorem/заглушек; заголовок — выгода, не «Добро пожаловать»;
  конкретные числа вместо прилагательных.
- **Типографика:** ≥2 различимых уровней; body ≥16px; ≤2 семейств; масштаб 1.25–1.333.
- **Сетка:** отступы из шкалы 4/8px; одинаковые межсекционные ритмы; выравнивание по сетке.
- **Цвет:** контраст текста ≥4.5:1; один акцентный цвет; фоны не спорят.
- **Перф:** LCP <2.5s; изображения сжаты и с размерами; шрифты не прыгают (font-display).

P0-критерий красный → счёт не может считаться проходным, независимо от %.

## 3. Видение-петля (обязательная)

После каждой сборки:
1. Скриншоты на 375 и 1440 (browser/Playwright).
2. Критик с vision (точечная vision-модель канона) получает скриншоты +
   скоркард → возвращает список красных критериев с конкретикой («CTA ниже fold
   на 375», «межсекционный отступ 13px вне шкалы»).
   Проверенная команда критика:
   `hermes chat --oneshot -Q --no-restore-cwd --image <скрин> -m gpt-6-luna --provider gpt-free --query-file <промпт-скоркард>`
   (точечно; free-пул думает минуты — гонить несколько скринов параллельно фоном).
   Фолбэк при 402/лимитах: `-m free/gpt-6-luna --provider apinex` (критик тогда сам
   делает пиксельный разбор PIL/numpy + WCAG-замеры — для типографики и контраста
   это даже точнее; честность оговорки «не глазами» — норма).
3. Фикс только по списку. Повтор.
4. **Бюджет: 3 цикла.** Счёт не растёт между циклами → СТОП, эскалация владельцу
   с парой скриншотов и дельта-списком. Не полировать вечно.

## 4. Порог сходимости

- **Ship: ≥85% AND все P0 зелёные.**
- 70–84% после 3 циклов → владельцу: текущий скрин vs якорь, конкретные
  недостающие пункты, оценка стоимости закрытия. Решение «выпустить/дожать» —
  за владельцем, не за агентом.

## 5. Независимость и якоря

- Генератор не выставляет себе design-pass: визуальную оценку даёт только
  отдельный критик (QA/vision), как R1 в коде.
- Якоря: `canon/design/anchors/<vertical>/` — 3–5 эталонных скриншотов на
  вертикаль, выбираются один раз (design предлагает, владелец утверждает).
  Проект без якоря не стартует.

## Правило

Визуальное качество — это петля «скриншот → зрячий критик → точечный фикс» с
порогом остановки. Чек-лист без глаз и бесконечная полировка дают 50–70% — всегда.
